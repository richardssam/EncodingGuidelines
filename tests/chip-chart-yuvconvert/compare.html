Comparing YUV conversion approaches.

This is comparing different ways to do the YUV conversion. We are doing it in both 420p and 444p since 444p is a fairer binary image comparison. The takeaway should be to use the libswscale filter. The code to generate these files is here.

yuv422p10le encodes

Default Encode (terrible)

Basic ffmpeg conversion with no colour arguments. ffmpeg converts using bt601 and leaves the file untagged, but players will typically assume bt709 for HD, giving significant color changes from the PNG file.

Default Encode + colour tags

No filter, but with the colour tagging arguments. Since FFmpeg 7.1 -colorspace bt709 also sets the matrix used by the auto-inserted libswscale conversion, so this is now correct. Before FFmpeg 7.1 it only tagged the file, and the pixels were still converted with bt601, giving the same result as the default encode.

ffmpeg flags to add: -color_range 1 -colorspace bt709 -bsf:v h264_metadata=colour_primaries=1:transfer_characteristics=13

zscale filter

Using the zscale (zimg) filter for the matrix and range conversion. zscale does not have the libswscale bias when converting to limited range, so white lands on the specification value. The decode back to RGB also uses zscale. Needs an ffmpeg built with --enable-libzimg.

ffmpeg flags to add: -vf "zscale=matrixin=709:matrix=709:rangein=full:range=limited:filter=spline36" -color_range 1 -colorspace bt709 -bsf:v h264_metadata=colour_primaries=1:transfer_characteristics=13

Full creation commandline:
ffmpeg -y -r 1 -i ../sourceimages/chip-chart-1080-noicc.png -vf "zscale=matrixin=709:matrix=709:rangein=full:range=limited:filter=spline36" -c:v libx264 -preset placebo -qp 1 -x264-params "keyint=15:no-deblock=1" -pix_fmt yuv422p10le -qscale:v 1 -color_range 1 -colorspace bt709 -bsf:v h264_metadata=colour_primaries=1:transfer_characteristics=13 ./chip-chart-yuvconvert/zscale.mp4
